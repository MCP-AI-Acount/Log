# 자동 업로드 실패 복구 규칙

- 자동 업로드 파이프라인은 실패를 복구 가능한 구조로 반환해야 한다.
- SNS 게시 전 품질검사가 실패하면 업로드를 차단하고 `social_skipped: true`를 반환한다.
- 실패 응답에는 최소한 다음 필드를 포함한다.
  - `ok: false`
  - `stage`: 실패 단계
  - `error`: 짧은 실패 요약
  - `quality_errors`: 품질검사 실패 목록
  - `artifacts`: 생성·누락된 주요 산출물 상태
  - `retry_command`: 수정 후 재실행할 명령
  - `next_action`: 다음 조치
- N8n이나 에이전트는 `ok: false`를 성공으로 간주하지 않는다.
- 실패 후에는 원인을 고치고 같은 최종 목적을 달성할 때까지 재실행한다.

## 기록 판단

- 장점: 같은 실패를 성공으로 착각하지 않고, 에이전트/N8n이 실패 후 바로 코드 수정·재실행할 수 있다.
- 단점: 실패 응답과 로그가 조금 길어지고, 일회 테스트에서 의도적 실패도 명시적으로 fail 처리된다.
- 추천도: ★★★★★ 5.0/5
