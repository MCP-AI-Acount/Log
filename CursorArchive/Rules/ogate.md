## O0~O4 출력 게이트

| 블록 | 발동 조건 | 내용 |
|------|----------|------|
| 💬 **O0 · 이해** | 요청 항목 2개 이상, 또는 질문+작업 혼합 시. 위 조건 미해당 시 생략. | 요청을 번호로 인덱싱 — 질문은 즉답(주관식), 실행 항목은 나열(객관식). |
| ✅ **O1 · 실행** | Write / Shell / MCP / git / 위임 실행 발생 시 항시. | O0 발동 턴: 인덱스 참조(`1 →` 형식). 미발동 턴: 한 줄 요약. 직접 실행 / 위임(`위임: [persona] → [작업]` + 수신 확인) 분기 명시. |
| 👤 **O2 · 사용자** | 사용자와의 관련성이 필수인 경우. 해당 없으면 생략. | 지시 모호해 확인 필요 / 기존 맥락·규칙에 반하는 경우 / 선택 필요(상충 관계 포함) / 권한 초과 / 복구 추가 작업 필요 |
| 📋 **O3 · 나머지** | 아래 해당 시. 없으면 생략. | ① O0 언급 작업 중 미완료 ② O0 미언급 추가 작업 잔여 ③ 미완료 NTD 중 이번 세션 처리가 더 효율적인 항목 ④ O2 미결 항목 |
| 🚪 **O4 · 세션** | Write / Shell / MCP / git / 위임 실행 발생 시 매 턴 끝. **항시 필수. 태그만.** | `경고` / `진행` / `마무리` / `완료` |

**3단 마무리**: 커밋-머지-푸시 / 옵시디안(Sessions·master-thread·next-session-prime 갱신) / NTD 정리

**K-4 토큰 절약**:
- 파일 동시 수정 3개 이하 (`VAL_MAX_MOD_FILES`=3)
- 인사말·서술형 줄글 배제
- 승인된 계획 실행 턴: 재설명·재탐색 금지, delta만

### O4 판정 기준

| 판정 | 조건 |
|------|------|
| **경고** | O3 존재 + 해당 항목 진행이 새 세션 시작보다 토큰 비효율 (컨텍스트 과부하·세션 전환·NTD defer 결정 포함) |
| **진행** | O3 존재 + 경고 아닌 경우 |
| **마무리** | O3 없음 + 3단 마무리 미완 |
| **완료** | O3 없음 + 3단 마무리 완료 |

**O4 금지**: 「~할까요」「알려주시면」「원하시면」등 선택지·질문 → O2로 이동.

## O2-O3 분리 원칙

**원칙 1**: 유저 결정·확인·손 **없어도 결과 동일** → **O2 금지 · O1 자동**.  
**원칙 2**: 선택·확인에 따라 결과가 달라짐 → **O2만** (O3·O4 금지).  
**원칙 3**: tier 약정 밖·다음 세션 → **O3-S** `다음 세션 / DEFER — {한 줄}`.

| 출력 유형 | O2 | O3 | O1 |
|-----------|-----|-----|-----|
| force push·secrets·D-10 트레이드오프 | ✅ 전문 | ❌ | ❌ |
| AI defer·잔여·자동·누락 고지 | ❌ | ✅ O3-S | — |
| verify·lint·F/N 무트레이드오프 fix | ❌ | ❌ | ✅ 즉시 |

## 시지프스 (세션 미션 루프)

> 정본: `projects/_platform/TALK_AUTO_SISYPHUS.md`

**미션 2티어**:
- **S1** — 세션 전체 미션 (`0_Config/next_session_missions.json`)
- **S2** — 이번 O0에서 파싱한 명시 미션

**O3 내용 분기**:
- **O2 있음** → O3 = **S2 명시 미션** 잔여
- **O2 없음** → O3 = **S1 세션 미션** 잔여

**루프 조건** (O4 판정과 연동):
- O4 = `진행` + O2 비움 → `(바로-가능)` 항목 자동으로 다음 O0 삼아 루프
- O4 = `마무리` → 시지프스 리포트 출력 + `next_session_missions.json` 갱신
- O4 = `완료` / `경고` → 루프 종료

**시지프스 리포트** (O4 `마무리` 아래):
```
[루프 횟수] N턴 · [튕겨남] Y/N · [미션 잔여] ... · [O-gate] PASS/FAIL
```

**[튕겨남] 처리**:
- Y: 착수조차 못 한 S2 미션 → `cc_ntd.json` pending 최상위 등록 (`priority: high` 강제)
- N: 리포트 그대로

**미완료 항목 NTD 기록** (O4 `마무리`·`경고` 시):
- `progress_snapshot.subject` / `bounce_reason` / `user_context` / `resume_hint`

**O-gate × 시지프스**: Samsara > 시지프스 > O-gate. CC는 behavioral priming으로만 집행.

**금지**: 루프 중 O2에 유저 질문 혼입.

## O-gate 준수 강화 규칙

### 집행 현황
| 규칙 | 집행 방식 | 훅 |
|------|-----------|-----|
| O1·O4 존재 여부 | `[Hook]` | `cc-stop-ogate-detect.sh` (Stop async) |
| O4 판정 정확도 | `[자기집행]` | — (의미 판단, hook 불가) |
| O2 오남용 방지 | `[자기집행]` | — |
| O3 NTD 스캔 범위 | `[자기집행]` | — (현재 대화 범위 제한) |

### 판정 실패 패턴 (자기집행 체크리스트)
- **O4 누락**: Write/Shell/MCP/git 발생 턴에 O4 태그 없음 → `cc-stop-ogate-detect.sh` 감지
- **O4 경고 미발동**: O3 항목 존재 + 남은 작업이 명백히 새 세션이 유리한데 `진행` 출력 → 자기판단 필수
- **O4 경고 과잉**: O3 없거나 토큰 비효율 아닌데 `경고` → `진행`으로 정정
- **O2 오남용**: 유저 확인 없어도 AI가 결정 가능한데 O2에 넣음 → O1 자동으로 이동
- **O3 NTD 전체 스캔**: 현재 대화 무관 NTD 항목을 O3에 포함 → 금지, 현재 대화 범위만

### O4 경고 판정 자기진단 (매 턴)
O3 항목이 있을 때 다음 질문:
1. 해당 O3 항목을 이 세션에서 계속하면 컨텍스트 비용이 새 세션 시작보다 높은가?
2. 유저가 이미 "다른 세션" / "나중에" / NTD defer 지시를 내렸는가?
3. 세션 전환 결정이 이미 내려진 상태인가?

→ 셋 중 하나라도 YES → **`경고`** 즉시 출력.
